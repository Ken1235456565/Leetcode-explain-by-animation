# 如何科学刷题

> 本文根据灵茶山艾府在力扣发布的《[如何科学刷题？](https://leetcode.cn/discuss/post/3141566/ru-he-ke-xue-shua-ti-by-endlesscheng-q3yd/)》整理。内容以学习笔记和行动指南的形式重新编排，建议结合原文及其配套题单学习。

## 一、总体原则

科学刷题的核心不是盲目追求题量，而是让题目难度与当前能力匹配，并通过专题练习、复习和实战检验形成持续的正反馈。

- 基础语法和常用库函数还不熟悉时，先完成力扣官方的编程入门题单，其中数据库题可以跳过。
- 优先按专题练习。同一种算法通常可以解决一组相似问题，集中训练更容易理解其共性和本质。
- 采用“螺旋上升”的方式学习：先覆盖各专题的基础题，再逐渐提高难度。
- 新手优先完成难度分不超过 1700 的题目。基础稳定后，再处理融合多个知识点的高难题。
- 不必要求第一次就理解所有题目。暂时无法掌握的题可以先跳过，积累一段时间后再回来复习。

## 二、方法 A：专题训练

专题训练适合新手建立完整的知识体系，也是前期最主要的刷题方式。

### 推荐的新手路线

| 顺序 | 专题 | 必学内容 | 说明 |
| --- | --- | --- | --- |
| 0 | 编程入门 | 基本语法、常用库函数 | 数据库题可以跳过 |
| 1 | 滑动窗口 | 定长滑动窗口、不定长滑动窗口 | 优先完成难度分不超过 1700 的题目 |
| 2 | 二分算法 | 二分查找 | 二分答案较难时可以暂时跳过 |
| 3 | 常用数据结构 | 枚举技巧、前缀和、栈、队列、堆 | 建立解决基础问题的工具箱 |
| 4 | 链表、树与回溯 | 二叉树 DFS | 理解递归，为动态规划做准备 |
| 5 | 网格图 | 网格图 DFS | 进一步熟悉递归和搜索 |
| 6 | 链表、树与回溯 | 回溯 | 掌握选择、递归、撤销选择的过程 |
| 7 | 动态规划 | 入门、背包、划分、状态机、区间、状压等前六类内容 | 可以把难度上限放宽到 2000 |

动态规划是很多初学者的难点，需要靠持续练习建立状态设计能力。原作者建议至少完成约 100 道动态规划题，才算初步入门。

完成上述路线后，就已经具备了较完整的基础，可以按照兴趣或短板继续学习其他专题。

### 完整专题地图

1. 滑动窗口与双指针：定长、不定长、单序列、双序列、三指针、分组循环。
2. 二分算法：二分查找、二分答案、最小化最大值、最大化最小值、第 K 小。
3. 单调栈：基础应用、矩形面积、贡献法、最小字典序。
4. 网格图：DFS、BFS、综合应用。
5. 位运算：基础、性质、拆位、试填、恒等式和位运算思维。
6. 图论：DFS、BFS、拓扑排序、基环树、最短路、最小生成树、网络流。
7. 动态规划：入门、背包、划分、状态机、区间、状压、数位、数据结构优化、树形、博弈、概率期望。
8. 常用数据结构：枚举技巧、前缀和、差分、栈、队列、堆、字典树、并查集、树状数组、线段树。
9. 数学算法：数论、组合、概率期望、博弈、计算几何、随机算法。
10. 贪心与思维：基本策略、反悔贪心、区间问题、字典序、数学、构造和思维题。
11. 链表、树与回溯：前后指针、快慢指针、DFS、BFS、树的直径、最近公共祖先。
12. 字符串：KMP、Z 函数、Manacher、字符串哈希、AC 自动机、后缀数组、子序列自动机。

### 如何学习一个新专题

可以把专题中的第一道题当作例题：先学习题解中的概念、模板和推导过程，再把后续题目作为配套练习。学习时不要只记代码，还要总结以下内容：

- 这类问题有哪些识别信号？
- 为什么该算法可以解决它？
- 状态或变量分别表示什么？
- 正确性依赖哪些不变量？
- 时间复杂度和空间复杂度是多少？
- 如果题目条件变化，原方法是否仍然适用？

## 三、方法 B：随机训练

专题训练会提前暴露题目类型，而真实比赛和笔试不会提示应该使用哪种算法。因此，通过新手阶段后，应穿插随机训练，锻炼识别题型和选择算法的能力。

建议做法：

1. 打开按难度选题的练习页面。
2. 关闭算法标签，避免提前获知题型。
3. 选择与自己水平匹配的难度区间。
4. 独立判断知识点、设计方案并完成代码。
5. 复盘误判的题型和遗漏的知识点。

随机训练的优点是更接近实战，可以检验学习成果、发现知识盲区；缺点是知识点比较零散，不适合代替系统的专题学习。比较合理的方式是以专题训练为主，每隔一段时间安排一次随机训练。

## 四、方法 C：面试突击

如果面试临近、时间有限，可以优先完成力扣 HOT 100。这些题覆盖大量经典面试模型。

完成 HOT 100 后如果还有时间，再练习“面试经典 150 题”。两个题单存在不少重复题，可以利用重复题检查自己能否独立、快速地写出正确解法。

## 五、遇到题目没思路怎么办

思考多久再看题解没有统一标准，可以是十分钟，也可以是数小时。关键在于看题解后进行有效复盘：

- 如果题解使用了自己没见过的技巧，就把它加入知识库，并找相似题巩固。
- 如果解法在能力范围内，只是临场没想到，可以继续思考，或换一个时间段再尝试。
- 离开问题一段时间后，大脑仍可能在无意识中处理它，这种现象称为“孵化效应”。
- 看懂题解不等于真正掌握。关闭题解后独立重写，并在几天后再次完成，才能检验是否吸收。

很多题没有思路并不代表不适合学算法。算法能力需要长期积累。新手应先做难度分低于 1700 的题，对暂时无法理解的内容做好标记，之后再回顾。

## 六、根据数据范围估算复杂度

通常可以粗略按每秒约执行 $10^8$ 次基础运算来估计；Python 的可承受运算量往往还要低一个数量级。实际表现也会受到常数、语言、数据结构和测试环境影响，例如哈希表通常比数组访问更慢。

| 数据规模 | 可考虑的时间复杂度 | 常见算法 |
| --- | --- | --- |
| $n \le 10$ | $O(n!)$ 或指数级 | 回溯、暴力搜索 |
| $n \le 20$ | $O(2^n)$ | 状态压缩动态规划 |
| $n \le 40$ | $O(2^{n/2})$ | 折半枚举 |
| $n \le 10^2$ | $O(n^3)$ | 三重循环动态规划、Floyd |
| $n \le 10^3$ | $O(n^2)$ | 二重循环动态规划、背包 |
| $n \le 10^5$ | $O(n\log n)$ | 排序、二分、堆以及大量常见算法 |
| $n \le 10^6$ | $O(n)$ | 线性动态规划、滑动窗口 |
| $n \le 10^9$ | $O(\sqrt n)$ | 试除法判断质数等 |
| $n \le 10^{18}$ | $O(\log n)$ 或 $O(1)$ | 二分、快速幂、数学公式 |

复杂度表只能帮助缩小思考范围，不能单独决定算法。还要结合题目的结构、单调性、状态数量、查询次数和内存限制进行判断。

## 七、算法面试答题流程

算法面试不仅考察是否能写出正确代码，也考察沟通、需求澄清、方案设计和验证能力。可以按照下面的顺序推进。

### 1. 主动询问示例

先请面试官提供输入、输出示例。如果没有现成示例，可以自己构造一个简单示例，并与面试官确认理解是否正确。

### 2. 明确接口和数据类型

确认以下信息：

- 输入和输出分别是什么类型？
- 方法签名是否已经确定？
- 输入是数组、字符串、集合，还是自定义对象？
- `Node`、`TreeNode`、`ListNode` 等结构如何定义？
- 节点是否包含额外字段，例如父指针、权重或访问标记？
- 函数是返回新对象，还是直接修改传入对象？

不要根据常见的力扣模板自行假设数据结构，面试题中的节点定义可能有所不同。

### 3. 确认输入和输出约束

重点询问：

- 输入规模的上下限是多少？
- 元素的取值范围是什么？
- 输入是否有序，是否允许重复？
- 输入是否一定合法？
- 是否需要返回任意一个答案、全部答案，或满足特定顺序的答案？
- 时间和内存是否有特殊限制？

约束通常决定可接受的复杂度，也是选择算法的重要依据。

### 4. 讨论边界和极端情况

在设计方案前，主动列出需要处理的特殊情况：

- 输入为 `null`、空数组、空字符串或空树。
- 只有一个元素或一个节点。
- 数值达到最小值或最大值，是否可能溢出。
- 所有元素相同、严格递增或严格递减。
- 树极度不平衡，递归是否会造成栈溢出。
- 图中存在环、重边或不连通部分。
- 是否允许修改输入，修改后是否需要恢复。
- 是否存在内存限制或原地算法要求。
- 数据结构是否有额外语义，例如树节点的父指针、Trie 的单词结束标记，或者跳表的多层指针。

与面试官确认哪些情况需要支持，避免解决错误的问题。

### 5. 从暴力解法或手工求解开始

先用一个小例子手工求解，明确最直接的处理过程，再将其概括为暴力算法。说明：

- 暴力方案如何枚举答案或模拟过程。
- 为什么它能够得到正确答案。
- 它重复进行了哪些计算。
- 时间或空间瓶颈在哪里。

暴力解法可以作为正确性基线，也为优化提供清晰的出发点。

### 6. 推导优化方案

根据暴力解法的瓶颈，寻找能够避免重复工作的算法或数据结构。例如：

- 重复查找：考虑哈希表、集合或预处理。
- 在有序空间中查找：考虑二分查找。
- 反复获取最大值或最小值：考虑堆或单调数据结构。
- 重叠子问题：考虑动态规划或记忆化搜索。
- 重复计算区间信息：考虑前缀和、差分、树状数组或线段树。
- 枚举连续区间：考虑滑动窗口或双指针。
- 状态和关系组成网络：考虑图搜索、拓扑排序或并查集。

复杂度优化不是机械地要求把 $O(n)$ 降到 $O(\log n)$ 或 $O(1)$。例如，哈希表只能将某些查找操作的平均复杂度降为 $O(1)$，读取全部输入本身通常仍需要 $O(n)$。应结合输入约束、问题结构和复杂度下界判断目标是否合理。

提出优化方案后，先用语言描述核心步骤、正确性依据和预期复杂度，并与面试官确认方向。

### 7. 获得许可后再写代码

在开始实现前明确询问：“如果这个方案没有问题，我现在可以开始写代码吗？”

在面试官说出类似 “Go ahead” 的明确许可之前，不写任何代码，包括伪代码。等待期间继续讨论方案、数据结构和边界条件。

### 8. 编码时解释思路

获得许可后再开始编码，同时保持有效沟通：

- 说明当前正在实现方案的哪一部分。
- 解释变量、数据结构和关键分支的作用。
- 遇到选择时说明权衡。
- 提前指出可能发生的越界、空指针或溢出问题。
- 不要逐字朗读正在输入的代码，应解释代码背后的思考。

### 9. 手动运行、测试和调试

代码完成后不要立刻宣布结束。使用前面确认的示例逐步执行：

1. 写出关键变量或数据结构的初始状态。
2. 按照代码执行顺序更新状态。
3. 检查循环边界、索引、指针和终止条件。
4. 验证结果是否与预期一致。
5. 再选择至少一个边界案例进行验证。

如果环境允许，可以编写简单的单元测试断言。测试至少应覆盖正常案例、最小输入、空输入以及容易出错的极端案例。

### 10. 分析时间和空间复杂度

最后说明：

- 时间复杂度，以及它由哪些循环、递归或数据结构操作决定。
- 空间复杂度，区分返回结果所需空间与额外辅助空间。
- 递归调用栈占用的空间。
- 平均复杂度与最坏复杂度的区别，例如哈希表操作。
- 如果约束发生变化，当前方案是否仍然适用。

### 面试流程速记

> 示例 → 接口 → 约束 → 边界 → 暴力 → 优化 → 请求编码许可 → 边写边讲 → 手动验证 → 复杂度分析

## 八、可执行的日常流程

每次练习可以按下面的流程进行：

1. 选择当前专题中与能力匹配的题目。
2. 阅读题意，分析数据范围和目标复杂度。
3. 独立思考并记录尝试过的方向。
4. 实现、调试并通过测试。
5. 总结识别信号、核心思路、易错点和复杂度。
6. 对看过题解或未独立完成的题做好标记。
7. 隔几天重新独立完成重点题。
8. 定期进行无标签随机训练，检验是否能识别题型。

最终目标不是记住每道题，而是看到新问题时，能够从约束和结构出发，识别可用工具，设计并验证一个满足复杂度要求的解法。
